# Hackathon brief (condensed checklist, FinTech: RL environments for financial-audit agents)

- Build a reproducible simulator: synthetic company docs, investigation tools, hidden financial errors, reward. Environment only; weight training optional, gives no points; no paid APIs/GPU; no claims of model improvement without controlled held-out comparison.
- >=4 independently configurable error types: duplicate invoices; missing/partial payment allocation; wrong FX date or rate; wrong reporting period. Two interacting-error scenarios (e.g. partial payment in another currency at period boundary). Clean companies and plausible correct distractors: split payments, refunds, legit recurring amounts.
- First a coherent hidden company history, then docs and errors with recorded causal change. Truth describes real discrepancy and available evidence; never require an unavailable fact. Vary names, IDs, order, amounts, currencies, time zones, error combinations. Hard enough to need evidence analysis, not unsolvable.
- Episode = one company, one period. Suggested 200-2000 postings, 20-200 docs, 0-12 errors.
- manifest.json: schema_version, episode_id, base_currency, period_start/end, timezone, record/doc counts, rounding rules. Time ISO-8601 with offset; money integer minor units with currency exponent; FX rates decimal strings; no cross-currency comparison without conversion.
- ledger.csv(row_id,timestamp,account,debit_minor,credit_minor,currency,entity_id,invoice_id,payment_id); invoices.jsonl(doc_id,invoice_id,entity_id,issued_at,due_at,currency,total_minor,line_items); payments.jsonl(doc_id,payment_id,timestamp,currency,amount_minor,invoice_refs); fx.csv(date,source_currency,target_currency,rate); policy.json(rate date choice, period boundaries, rounding). Missing refs explicit null.
- Private: truth.json(issue_id,type,affected_ids,expected_amount_minor,currency,acceptable evidence sets); provenance.json (generation history and injected changes). Agent never sees them or the seed. Grader runs outside agent process; records read-only via narrow tool interface. No leakage via observations, paths, errors, debug info, reward explanations during closed run.
- reset(seed, config)->(observation, info); first obs: task, manifest, short policy, remaining budget. step(action)->(obs,reward,terminated,truncated,info), JSON Gymnasium-style. Same seed/config/version/actions reproduce records, transitions, rewards. Reset isolates state.
- Actions: list_records(table,cursor,limit); get_record(table,id); get_document(doc_id); calculator(expression); submit(findings). Page max 50 rows, stable cursors. Calculator arithmetic/decimals only. Unknown id/action -> bounded error, consumes a step. Observation only requested records, result/error, remaining steps. No shell/SQL/FS/internet.
- Max 100 steps incl. submit. submit -> terminated=true. Step/time limit -> truncated=true and empty final answer. Zero reward for exploration. Terminal reward to policy only in open training mode; in evaluation reward and diagnostics stay with grader until run ends. No correctness hints.
- findings.json {episode_id, findings:[{type, affected_ids, claimed_amount_minor, currency, evidence_ids, explanation}]}. Max 30 findings, 10 evidence ids, 1000 chars explanation. Bad structure -> episode ends, reward -1, error in grader log.
- One-to-one matching. TP needs correct type, canonical affected_ids, amount within explicit tolerance, currency, and >=1 complete acceptable evidence set. Unmatched/repeated -> FP; missed -> FN. Publish normalization, tolerance and ambiguous-match code.
- P=TP/(TP+FP), R=TP/(TP+FN), F1=2TP/(2TP+FP+FN); zero denominators -> 0; truth & findings empty -> F1=1; truth empty, findings non-empty -> F1=0. Terminal reward = clip(2*F1-1-0.002*inspection_steps,-1,1). Experimental reward allowed but shared one shown separately. Reward depends on fields/evidence, not persuasive text.
- Tests must show: full correct answer with evidence > silence on erroneous books; silence > false accusations on clean; duplicates no gain; flag-everything bad; step economy only slightly differentiates equal answers. Check guessed IDs, unsupported evidence, currencies, re-submit, bad input, timeout.
- Jury runs: fixed-seed random explorer, simple reconciliation, flag-everything attack, grader-only oracle on 20 hidden episodes (5 clean, 5 interacting) + 20 paired checks changing order and IDs. Hidden seeds, new parameter combinations, benign transforms.
- Minimum: generator (4 types, 2 interactions, clean, distractors); env with reset/step, actions, 100-step limit; shared matcher+reward with attack tests; recorded trajectories without truth in observations; official check offline without paid APIs/GPU; container instructions and single check command. Suggested limits: Python 3.11, 2 CPU, 4 GB RAM, no GPU, 1 GB, 60 s/episode, 100 steps.
- Deliver: source + license + pinned deps; README with container instructions and single check command; matcher & reward code, schemas, policies; 10 open train + 10 dev episodes; tests; four baseline policy adapters; trajectories.jsonl (episode_id, step, action, observation, reward, terminated, truncated); design note; demo (scripted policy enough).
- Scoring 100: Contract & isolation 25 (20 fixed checks: reset/step, schemas, limits, termination, bad input, no leaks); Data & truth 25 (20 hidden episodes: accounting identities before error, declared discrepancy after, independent evidence sufficiency; contradictory/unsolvable data != difficulty); Reward robustness 25 (matching, clean cases, FP, duplicates, cost, attacks); Reproducibility & generalization 15 (20 paired checks: exact seed/action replay; permutation and ID change preserve oracle answer and reward); Engineering & explanation 10 (one-command run, config versions, trajectory logs, measured failure analysis, honest limitations). Leaks, writes into grader, real financial data, or broken core block scoring. Show P, R, F1, return, steps, time of agents as diagnostics.
- All companies/people/money fictional; no real cards/payments/PII. Not a professional audit opinion. UI and unproven training gains earn nothing.
